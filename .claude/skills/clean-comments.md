# 🧹 스킬: 주석 및 클린 코드 정밀 타격 (Clean Comments)

에이전트는 코드 커밋 직전, 본 스킬을 실행하여 코드베이스에 남아있는 'LLM 특유의 오염된 주석'과 잉여 코드를 완벽히 소거해야 합니다. 에이전트의 자율 판단이 아닌 아래의 엄격한 **분류 기준(Rule-based)**에 따라 주석을 삭제/수정하십시오.

## 🚨 1. 절대 삭제 대상 (MUST DELETE)

에이전트는 코드 스캔 시 아래 패턴의 주석을 발견하면 **100% 삭제**해야 합니다.

### 1.1. 대화 맥락 및 의사결정 과정 노출 (LLM Hallucination)
설계 결정이나 프롬프트 대화 과정은 코드에 남길 것이 아니라 PR(Pull Request) 본문에 적어야 합니다.
* **[삭제 대상 예시]** 
  * `// A 방식으로 구현하기로 했으나 B 방식으로 우회함`
  * `// 의도적으로 이 부분은 구현을 생략함`
  * `// PRD 요구사항에 따라 작성됨`
  * `// MapStruct 대신 BasicMapper를 사용하기로 결정함`

### 1.2. 단순 나열형 및 작업 중계형 주석 (Play-by-play)
코드가 하는 일을 그대로 인간의 언어로 중계하는 주석은 가독성만 해칩니다.
* **[삭제 대상 예시]**
  * `// 1. 유저를 찾는다. 2. 트윗을 생성한다. 3. 저장한다.`
  * `// 여기서부터 Controller 메서드 시작`
  * `// userRepository를 호출하여 id로 유저 검색`

### 1.3. 다중 레이어 중복 주석
동일한 내용을 Controller, Service, Repository 세 곳에 복사-붙여넣기 한 경우, 가장 핵심이 되는 비즈니스 로직(Service) 한 곳에만 남기고 나머지는 삭제합니다.

### 1.4. 방치된 코드 (Dead Code)
* **[삭제 대상 예시]** `// int retryCount = 0;` 처럼 주석 처리된 소스 코드.

---

## ✅ 2. 보존 및 보강 대상 (MUST KEEP / ENHANCE)

아래의 기준에 부합하는 주석만 허용됩니다.

### 2.1. 도메인 정책의 '의도(Why)'
코드로 표현하기 힘든 복잡한 비즈니스 규칙의 배경은 남겨둡니다.
* **[허용 예시]** `// 트위터 정책상 리트윗의 리트윗은 원본 트윗을 참조해야 하므로 depth를 1로 고정함`

### 2.2. 표준 Javadoc (인터페이스 및 Controller)
외부에 노출되는 Controller 엔드포인트와 Service 인터페이스에는 표준 Javadoc을 강제합니다.
```java
/**
 * 특정 유저의 피드를 페이징하여 반환합니다.
 * @param userId 대상 유저 ID
 * @param pageable 페이징 메타데이터
 * @return HeaderResponse로 감싸진 트윗 목록 (헤더에 총 페이지 수 포함)
 * @throws ApiRequestException 유저가 존재하지 않거나 차단된 경우
 */
```
